# STAGE 8.0 — Professional Model Preparation System

## Цель

Stage 8.0 начинает развитие STL Master как профессионального инструмента подготовки STL-моделей к печати. Изменения сделаны как фундамент: интерфейс разделяет операции, показывает параметры только в нужном контексте и не меняет backend/API/worker pipeline.

## UX-анализ Bambu Studio

Что полезно использовать:

- Инженерная логика: пользователь выбирает задачу, видит параметры только текущей операции и получает предсказуемый preview до запуска.
- Постоянная 3D-сцена как главный рабочий объект.
- Быстрые viewer-действия рядом с моделью: центрирование, поворот, снимок.
- Чёткое разделение подготовки, обработки и результата.

Что использовать нельзя:

- Копировать визуальную систему, компоновку и термины Bambu Studio.
- Переносить slicer-специфичные сущности, если STL Master пока не режет G-code.

Как реализовать по-своему:

- STL Master остаётся online-first инструментом: меньше производственных панелей, больше понятных задач подготовки модели.
- Split оформляется как операция подготовки модели, а не как часть slicer-процесса.

## UX-анализ OrcaSlicer

Что полезно использовать:

- Группировка профессиональных инструментов по смыслу.
- Подсказки на инструментах, чтобы не перегружать интерфейс постоянным текстом.
- Preview-режим перед применением тяжёлой операции.

Что использовать нельзя:

- Не копировать плотную slicer-навигацию и производственные панели.
- Не перегружать первый уровень настройками, которые нужны только опытным пользователям.

Как реализовать по-своему:

- Сложные параметры соединений открываются только при выборе соответствующего Split-режима.
- Для новых соединений используется архитектурная подготовка без обещания полной генерации там, где она ещё развивается.

## UX-анализ PrusaSlicer

Что полезно использовать:

- Cut workflow как отдельный режим: пользователь сначала задаёт плоскость, затем выбирает тип соединения.
- Ясная работа с результатами: основной пакет и отдельные дополнительные файлы.
- Простые, предсказуемые tooltips для инструментов viewport.

Что использовать нельзя:

- Не копировать PrusaSlicer UI и не превращать STL Master в slicer.
- Не смешивать параметры принтера, материала и G-code с задачей подготовки STL.

Как реализовать по-своему:

- Результат в STL Master строится вокруг ZIP-пакета: STL, JSON, TXT и Compare доступны рядом, но не конкурируют с главным действием.

## UX-анализ Meshmixer

Что полезно использовать:

- Mesh repair и plane cut как понятные операции над геометрией.
- Инструменты должны быть визуально связаны с моделью, а не спрятаны в длинный список.
- Preview до обработки снижает страх пользователя перед изменением модели.

Что использовать нельзя:

- Не копировать устаревшую плотную desktop-композицию.
- Не делать смешанную панель, где анализ, история, feedback и параметры видны одновременно.

Как реализовать по-своему:

- Правая панель остаётся контекстной: параметры появляются только при выбранной операции, история и техданные остаются за отдельными действиями.

## Какие идеи применены

- Операция Split разделена на отдельные пользовательские сценарии.
- Split preview включается для всех split-сценариев, а не только для старого режима.
- Настройки соединений показываются только для режимов, которым они нужны.
- Viewer toolbar получил подсказки с назначением и горячими клавишами.
- Результат подчёркивает главное действие: `Скачать ZIP`, ниже — дополнительные файлы `STL`, `JSON`, `TXT` и `Compare`.

## Новая архитектура операций

Операции в Studio сгруппированы как профессиональный workflow:

- Анализ: проверка модели перед обработкой.
- Ремонт: исправление сетки, AI-артефактов и поверхности.
- Оптимизация: вес, ориентация и подготовка формы.
- Разделение: плоский разрез и режимы соединений.
- Экспорт: пакет STL/ZIP/JSON/TXT как финальный результат.

Backend contract не изменён: отправка идёт через существующий `/api/v1/jobs/upload`, операции остаются массивом `operations`.

## Новая архитектура Split

Созданы frontend-presets поверх существующего `split_model` pipeline:

| Preset | Backend split_mode | lock_profile | Статус |
| --- | --- | --- | --- |
| Плоский разрез | simple | tongue_groove | готовый обычный разрез |
| Разрез со штифтами | pins | tongue_groove | использует существующие connector-параметры |
| Разрез паз-гребень | lock | tongue_groove | архитектура + существующий lock pipeline |
| Ласточкин хвост | lock | dovetail | архитектура профиля |
| Пазловое соединение | slots | wave | фундамент для пазлового профиля |

Все режимы используют одну цепочку:

`analyze → print_check → repair_mesh → split_model → prepare_package`

## Подготовленная архитектура соединений

Интерфейс поддерживает параметры:

- диаметр / размер соединителя;
- глубина;
- количество;
- отступ / зазор;
- автоматическая расстановка;
- ручная корректировка как подготовленный режим интерфейса;
- профиль: паз-гребень, ласточкин хвост, пазловый профиль.

Backend уже принимает `connector_size_mm`, `connector_depth_mm`, `connector_clearance_mm`, `connector_count`, `lock_profile`, поэтому Stage 8.0 не требует изменения API.

## Viewer Tooltips

Viewer toolbar получил подсказки:

- Центрировать — вернуть модель в центр viewport, клавиша C.
- Повернуть X — развернуть вокруг оси X, клавиша X.
- Повернуть Y — развернуть вокруг оси Y, клавиша Y.
- Повернуть Z — развернуть вокруг оси Z, клавиша Z.
- Поставить на стол — сбросить положение на рабочий стол.
- Очистить — убрать текущую сцену.
- Скриншот — сохранить PNG текущего viewport.

## Interactive Preview

При выборе любого Split-preset viewer переходит в режим подготовки:

- отображается секущая плоскость;
- сохраняется направление по выбранной оси;
- показываются connector hints для режимов со соединениями;
- появляется компактный badge с выбранным split-сценарием, количеством частей, осью и типом соединения;
- обработка не запускается до нажатия основной кнопки pipeline.
